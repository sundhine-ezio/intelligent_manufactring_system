# 制造系统感知、分析与决策平台需求规格说明

## 1. 编制目的

本文档将原始场景描述转换为可实施、可验收并可继续编写技术设计文档的需求。文档对需求进行统一归类，定义功能边界、性能指标、技术约束、优先级和实现可行性，并明确暂不纳入当前版本的内容。

## 2. 建设范围与版本策略

### 2.1 总体建设范围

系统面向制造企业的生产质量、设备状态和仓储物料管理，形成以下业务闭环：

1. 采集生产、设备和库存相关数据。
2. 对产品质量、设备运行和库存变化进行统计分析。
3. 按配置阈值生成质量、设备和库存预警。
4. 向维修人员、仓管、采购、销售和管理人员提供查询、处置和决策依据。

### 2.2 实施阶段

| 阶段 | 建设内容 | 优先级 |
| --- | --- | --- |
| 一期（MVP） | 库存台账与预警、产品合格率统计、设备状态监测、移动端查询和报警闭环 | P0 |
| 二期 | 库存需求预测、采购与销售建议、质量异常关联分析、机床工艺参数分析 | P1 |
| 三期 | 经验证的故障预测、工艺参数半自动调整、模型持续优化 | P2 |

一期必须能够独立运行和验收；二期、三期功能不得作为一期交付的前置条件。

## 3. 角色与权限

| 角色 | 核心权限 |
| --- | --- |
| 管理人员 | 查看全局经营、库存、质量、设备和报警汇总数据，查看分析报告 |
| 仓管人员 | 维护入库、出库、盘点和库存调整记录，查看库存预警 |
| 采购人员 | 查看库存、采购需求和缺料预警，登记采购单及处理状态 |
| 销售人员 | 查看成品库存、出货数据和积压预警，登记销售计划或订单摘要 |
| 维修人员 | 查看负责设备的状态和质量异常，确认、处理和关闭维修工单 |
| 安全员 | 查看和处置安全报警；该角色为原始需求的可扩展角色，是否纳入一期由业务方确认 |
| 系统管理员 | 管理用户、角色、设备、物料、阈值、数据源和系统参数 |

系统必须采用基于角色的访问控制。用户只能访问被授权的工厂、生产线、仓库、设备和业务数据。

## 4. 需求汇总与优先级

### 4.1 需求分类

| 需求域 | 对应原始场景 | 核心产出 | 一期纳入情况 |
| --- | --- | --- | --- |
| 物料与库存管理 | 场景需求2 | 库存台账、库存趋势、缺料/积压预警 | 全量纳入 |
| 产品质量检测 | 场景需求1 | 产品检测结果、合格率、良品率、质量预警 | 纳入基础能力 |
| 设备状态监测 | 场景需求1 | 设备状态、异常指标、维修工单 | 纳入基础能力 |
| 生产质量关联分析 | 场景需求1 | 质量异常与生产环节的关联分析 | 纳入规则版，精确诊断后置 |
| 需求预测与计划建议 | 场景需求2 | 采购、销售和库存趋势预测 | 二期纳入 |
| 机床工艺分析 | 场景需求3 | 温度、出液量、切屑时间和转速的关联分析 | 二期纳入监测版 |
| 机床自动控制 | 场景需求3 | 自动调整出液量和电机转速 | 三期候选，不作为当前承诺 |

### 4.2 优先级定义

- **P0：必须实现**。缺少该功能将导致一期核心业务无法运行或无法验收。
- **P1：应当实现**。对业务价值较高，但可在一期之后交付。
- **P2：条件满足后实现**。依赖足量数据、模型验证、现场安全审批或控制接口。

## 5. 功能需求

### 5.1 基础主数据与数据接入（P0）

#### 5.1.1 主数据管理

系统应支持维护以下基础对象：工厂、生产线、生产环节、设备、仓库、物料、产品、供应商、客户和计量单位。

每个对象应具有唯一编码、名称、状态和创建/更新时间。设备应关联所属生产环节、数据采集点和责任人员；物料应区分原料、半成品和成品。

#### 5.1.2 数据接入

系统应支持以下数据来源：

1. 通过数据库接口、HTTP API或文件导入接收库存、采购、销售和生产数据。
2. 通过标准化接口接收传感器数据，包括设备编号、测点编号、采集时间、数值和单位。
3. 接收摄像头或机器视觉服务输出的检测结果。原始图像可使用对象存储保存，业务数据库保存图像索引，不要求一期直接保存全部视频流。
4. 对来源不明、时间无效、单位不一致或字段缺失的数据进行校验，并记录失败原因。

### 5.2 库存、采购与销售管理（P0）

1. 系统应支持原料、半成品和成品的入库、出库、退库、盘点和库存调整。
2. 每笔库存变动必须记录物料、数量、单位、仓库、业务类型、关联单据、操作人员和操作时间。
3. 系统应按物料和仓库计算当前库存、可用库存、锁定库存和安全库存。
4. 系统应支持维护最低库存、最高库存、安全库存和预警天数。
5. 系统应支持登记采购计划、采购单状态、预计到货时间和实际到货数量。
6. 系统应支持登记销售计划或订单摘要、计划交付时间、已交付数量和未交付数量。
7. 当可用库存低于安全库存时，系统应生成缺料预警；当库存高于积压阈值或连续多个周期未发生有效出库时，系统应生成积压预警。
8. 仓管、采购、销售和管理人员应能按物料、仓库、时间和状态查询库存及相关业务记录。

### 5.3 产品质量检测与统计（P0）

1. 系统应接收单件产品的合格/不合格检测结果，并关联产品、批次、生产环节、设备、检测时间和检测来源。
2. 系统应支持记录缺陷类型、检测置信度、检测算法版本和图像索引；一期允许由外部机器视觉服务提供识别结果。
3. 系统应按批次、生产环节、设备和时间范围统计检测总数、合格数、不合格数、合格率和良品率。
4. 系统应统一采用以下初始计算口径：
	- 合格率 = 合格产品数量 / 已完成检测的产品总数量 × 100%。
	- 良品率 = 满足最终质量标准且未被返工或报废的产品数量 / 已完成检测的产品总数量 × 100%。
5. 当样本数量未达到最小统计量时，系统应标记“样本不足”，不得仅依据少量样本生成强结论。
6. 系统应支持配置产品、批次或生产环节的目标良品率和预警阈值。
7. 实际良品率低于阈值时，系统应生成质量预警，并关联对应批次、环节和设备。

### 5.4 设备状态监测与维修闭环（P0）

1. 系统应展示设备在线、离线、正常、预警、故障和维修中等状态。
2. 设备状态应至少依据心跳、关键传感器阈值和人工确认结果计算；状态变更必须保留历史记录。
3. 设备连续超过配置时间未上报数据时，应生成设备离线预警，并显示最后上报时间。
4. 系统应支持配置温度、压力、振动、电流等测点的正常范围、预警范围和故障范围；具体测点由设备清单确定。
5. 设备预警或质量预警发生后，系统应支持创建维修工单，记录异常现象、关联设备、责任人、优先级和截止时间。
6. 维修工单至少支持“待确认、处理中、待验证、已关闭、误报”状态。
7. 维修人员应能够填写故障原因、处理措施、备件使用、开始时间、结束时间和验证结果。
8. 系统应统计设备故障次数、平均处理时长、重复故障次数和工单逾期情况。

### 5.5 质量异常与生产环节关联分析（P1）

1. 系统应基于同一批次、生产环节、设备和时间窗口关联产品质量结果与设备测点数据。
2. 系统应优先采用可解释规则输出疑似异常环节，例如良品率下降同时伴随某设备测点超阈值。
3. 分析结果必须显示触发规则、关联数据、统计时间窗口和结果置信等级，不得将“疑似异常”直接表述为确定故障。
4. 一期只要求输出候选异常设备或环节，不要求系统自动给出唯一故障根因。

### 5.6 库存趋势预测与计划建议（P1）

1. 系统应按物料和统计周期展示历史消耗、入库、出库、库存和生产需求趋势。
2. 在具备连续历史数据后，系统可预测未来周期的物料需求和成品销售趋势。
3. 预测结果必须显示预测周期、使用的数据范围、预测值和可信区间或风险等级。
4. 系统可根据安全库存、预计消耗、在途采购和交付计划生成采购建议；建议必须由采购人员确认后才能转为采购计划。
5. 系统可根据成品库存、历史销量和销售计划生成销售或生产调整建议；系统不得自动修改销售计划或采购单。
6. 当历史数据不足、季节变化明显或预测误差超过配置阈值时，系统应提示预测结果不可用或仅供参考。

### 5.7 机床温度与工艺关联分析（P1）

1. 系统应采集机床编号、零件编号、采集时间、零件温度、出液量、电机转速、切屑时间和质量检测结果。
2. 系统应展示温度随时间变化曲线，并支持与出液量、转速、切屑时间和最终质量结果进行对比。
3. 系统应支持按批次或时间窗口分析温度、工艺参数和质量结果之间的统计关系。
4. 分析输出应明确为相关性分析，不得在缺少实验验证时直接宣称温度导致硬度、韧性变化或一定会造成质量缺陷。
5. 系统应支持人工记录工艺调整前后的质量结果，作为后续参数优化的数据基础。

### 5.8 移动端与通知（P0）

1. 移动端应支持登录、首页摘要、报警列表、报警详情、库存查询、设备查询和工单处理。
2. 管理人员应能查看库存、质量、设备和报警的汇总指标；业务角色只显示其权限范围内的数据。
3. 系统应支持站内通知；短信、第三方推送等外部渠道作为可选适配能力。
4. 报警通知应包含报警类型、级别、对象、发生时间、当前状态和处理入口。
5. 同一对象在配置时间窗口内重复触发相同规则时，系统应支持合并通知，并保留重复触发次数。

## 6. 性能与技术指标

以下指标作为一期设计和验收的初始目标；在完成设备数量、并发规模和网络条件调研后允许形成最终基线。

### 6.1 数据与接口指标

| 指标 | 一期目标 |
| --- | --- |
| 传感器数据接收延迟 | 正常网络条件下，从接入到入库不超过5秒 |
| 设备状态刷新周期 | 默认不超过10秒，具体由测点配置 |
| 产品检测结果入库延迟 | 外部算法返回后不超过5秒 |
| 库存业务数据入库 | 单笔业务提交后不超过3秒返回处理结果 |
| 数据完整性 | 关键业务记录不得静默丢失；失败数据必须记录重试或失败状态 |
| 接口可用性 | 关键接口月度可用性目标不低于99.5% |

### 6.2 查询与报警指标

| 指标 | 一期目标 |
| --- | --- |
| 常规列表查询响应时间 | 常用筛选条件下95%的请求不超过3秒 |
| 首页汇总查询响应时间 | 95%的请求不超过5秒 |
| 设备离线报警生成 | 超过离线阈值后不超过30秒生成 |
| 质量或库存预警生成 | 数据入库后不超过30秒生成 |
| 报警通知发送 | 报警生成后不超过60秒进入站内通知 |
| 报警记录可追溯性 | 每条报警均能追溯到规则、数据来源和处置记录 |

### 6.3 数据规模初始假设

技术设计应至少按以下规模进行容量评估：1000个设备、10000个传感器测点、每日100万条传感器记录、每日10万条产品检测记录、100个并发登录用户。若现场规模超过该假设，应重新进行架构和存储容量评估。

### 6.4 质量与模型指标

1. 产品质量识别准确率、召回率和误报率必须通过标注样本测试确定，不能仅凭算法名称作为验收依据。
2. 一期质量检测模块以“正确接收外部检测结果、正确统计和正确触发阈值”为必验项；视觉模型本身的指标需另行制定模型验收方案。
3. 库存预测功能上线前，应使用历史数据进行回测，并将平均绝对百分比误差或其他经确认的误差指标作为参考。
4. 故障定位和自动调参功能在没有现场验证数据前不得设置为硬性准确率承诺。

## 7. 技术实现约束

1. 推荐采用前后端分离架构：移动端或Web端负责展示与操作，后端提供鉴权、业务接口、统计分析和报警服务。
2. 事务型业务数据应使用关系型数据库；传感器时序数据应根据数据量选择时序数据库或带分区能力的关系型数据库。
3. 图像和视频等大文件应使用对象存储，数据库仅保存元数据和访问索引。
4. 数据接入服务应具备消息队列、重试、幂等和断点恢复能力，避免重复写入和瞬时断网造成数据丢失。
5. 统计计算应区分实时指标和离线报表，避免大范围历史查询阻塞实时报警。
6. 算法服务应通过独立接口提供检测结果，并携带算法版本、置信度和处理时间。
7. 所有关键操作、报警状态变更、库存调整和参数修改都必须记录审计日志。
8. 系统应支持配置化管理阈值、规则、数据保留时长和通知策略，避免将业务规则硬编码在客户端。

## 8. 不同需求之间的可行性分析

| 需求 | 可行性 | 主要依赖与风险 | 处理结论 |
| --- | --- | --- | --- |
| 库存台账、出入库和阈值预警 | 高 | 依赖基础物料和业务数据准确 | 一期P0，全量实现 |
| 产品合格率和良品率统计 | 高 | 依赖统一检测结果和计算口径 | 一期P0，先实现统计与规则预警 |
| 设备在线状态和阈值监测 | 高 | 依赖传感器接入和测点配置 | 一期P0 |
| 维修工单闭环 | 高 | 依赖责任人和处置流程确认 | 一期P0 |
| 质量异常关联设备 | 中 | 依赖批次、设备和时间数据对齐 | 一期规则版，二期优化 |
| 销售与采购趋势预测 | 中 | 依赖连续历史数据、季节性和订单数据 | 二期P1，必须支持人工确认 |
| 故障根因自动定位 | 中低 | 依赖大量标注故障样本和稳定工况 | 不作为一期承诺，先输出候选异常 |
| 温度与材料硬度/韧性关系推断 | 中低 | 需要材料、工艺和实验数据验证 | 二期仅做相关性分析 |
| 机床出液量和转速自动调整 | 低 | 涉及控制接口、设备安全、工艺边界和实时控制验证 | 三期候选，暂不纳入交付 |
| 基于摄像头的危险操作识别 | 中 | 依赖现场摄像头位置、标注数据和隐私审批 | 后续扩展，需单独立项验收 |

## 9. 剔除、降级与暂缓内容说明

### 9.1 从当前版本中剔除的内容

1. **直接自动调整机床出液量和电机转速**：剔除出一期和二期交付范围。该功能会直接影响设备运行和人员安全，且当前缺少设备控制接口、工艺安全边界、控制策略和现场验证数据。后续只能在人工确认、仿真验证和安全审批完成后，以三期受控功能重新评估。
2. **自动确定故障发生环节和唯一根因**：剔除“一期确定性诊断”表述。当前数据只能支撑基于规则的候选设备或环节提示，不能保证复杂生产条件下的唯一故障定位。
3. **自动生成并执行采购、销售调整计划**：剔除自动执行部分。系统只生成建议，由采购、销售或管理人员审核确认，避免预测误差直接造成经营业务变更。
4. **一期自研完整机器视觉和机器学习模型**：剔除模型研发本身作为一期基础交付内容。一期先定义标准检测结果接口并接入已有算法或人工录入结果；模型训练、标注和部署应单独形成算法子项目。

### 9.2 降级处理的内容

1. 将“预测分析”降级为带数据充分性提示的辅助分析，不作为无条件准确预测。
2. 将“温度影响硬度、韧性”降级为温度与工艺参数、质量结果的相关性分析，不直接输出材料性能结论。
3. 将“设备是否正常”拆分为设备在线状态、测点阈值状态和人工维修确认状态，避免用良品率单一指标替代设备诊断。
4. 将安全员危险操作识别保留为扩展方向；若纳入项目，必须补充行为清单、摄像头布置、隐私要求、误报处理和模型验收指标。

## 10. 一期验收标准

1. 能够维护物料、产品、设备、仓库和用户等基础数据，并按照角色限制访问范围。
2. 能够完成库存入库、出库、盘点和调整，库存余额与业务变动记录一致。
3. 当库存低于安全库存或超过积压阈值时，能够在规定时间内生成并展示预警。
4. 能够接收产品检测结果，并按批次、环节和设备正确计算合格率与良品率。
5. 当质量指标低于配置阈值时，能够生成质量预警并关联对应生产对象。
6. 能够接收设备数据，展示设备最新状态，并在数据超时后生成离线预警。
7. 维修人员能够从报警创建或接收工单，完成确认、处理、验证和关闭，且全流程可追溯。
8. 管理人员能够在移动端或Web端查看库存、质量、设备和报警汇总数据。
9. 系统达到第6章规定的初始响应、延迟和可追溯性指标。
10. 对被剔除或降级的功能，系统不得以自动控制、确定性诊断或无依据预测的形式对外承诺。

## 11. 后续技术设计前必须确认的问题

1. 一期实际接入的工厂、仓库、生产线、设备和测点数量。
2. 现有ERP、MES、WMS、设备控制系统和机器视觉系统的接口协议。
3. 产品、物料、批次、库存、采购和销售数据的主数据编码规则。
4. 良品率和合格率的最终业务定义，以及返工品是否计入分母或分子。
5. 各设备测点的采样周期、单位、阈值、离线判定时间和数据保留期限。
6. 预测所需的历史数据范围、销售订单来源和采购审批流程。
7. 移动端目标平台、通知渠道、网络环境和离线要求。
8. 图像、视频、人员信息及生产数据的隐私、权限和保存要求。
9. 三期自动控制是否具备可调用的设备接口，以及安全联锁和人工接管方案。
