# 演示路线与答辩笔记

## 5–8 分钟演示路线

1. 打开首页：本项目有物流、视觉、设备、订单和能源五个业务模块，对应七个指定任务与一个自定义任务。静态首页没有动画。
2. AGV：新增一台小车，新建“检测区→复检区”搬运任务，点击开始；选中小车高亮路径，暂停查看电量、磨损与任务，最后重置。解释此版按创建顺序派单、走固定通道，尚未实现最优调度和多车避碰。
3. 表面检测：加载龟裂或划痕示例，依次解释原图、滤波增强、边缘、候选区域；调整阈值更新预览；叠加人工标注。蓝框为简化处理候选，橙框为人工参考，不能混淆。
4. 上传：选择自己的 PNG/JPEG 图片，观察原图预览；点击尝试检测会提示未接入，不会产生预设识别框。
5. 物体定位：先启动 `python3 code/backend/server.py`，切换任务 05，选择一张 BlenderProc 测试图并点击“开始识别”；展示颜色、目标框、像素中心及限定条件下的 XYZ 估算。再上传普通照片，说明默认不提供 XYZ。
6. 订单：默认展示真实销售子集。选择商店或商品，切换日/周/月；生成最近七日重复示例，再切换均值示例。解释为什么没有显示“预测准确率”。
7. 能源：默认总用电 81.70 kWh，将加工设备 A 功率从 7.5 改成 10 kW，运行 6 小时，重新计算后总量应为 96.70 kWh。解释差值 15 kWh = (10 − 7.5) × 6。留空会报错，全部设零会显示零能耗且不显示占比。
8. 设备监测：说明需另找温度、振动、电流等传感器数据，当前保留规划页。最后介绍未来视觉通过工位编号生成搬运任务的联动。

## 常见提问

**为什么选择这一套技术？**

沿用老师的 Vue、Bootstrap、Axios 思路。任务 5 当前由 Python 标准库 HTTP 服务调用 OpenCV，接口和页面已接通；其他业务模块的正式 Django、数据库后端仍待接入。Node 服务只发送前端静态文件。

**任务排序、分配、路径规划有何不同？**

排序解决先运哪个任务；分配解决由哪辆车执行；路径规划解决从起点到终点怎么走。最短路径不自动意味着整个搬运系统总时间最短，还需考虑等待、装卸、冲突等约束。

**为什么现在的车可能同时经过同一条道路？**

此版只演示静态路线和状态，未实现带时间约束的多车避碰。需要预约表、时空搜索或冲突处理策略后才能证明安全性和效率。

**地图改变后为什么不用改每条任务？**

任务引用工位编号，编号再映射到地图中的停靠点。坐标和业务任务解耦。当前固定通道有几何限制，修改地图后仍需检查可通行性。

**图像标签有什么作用？**

标签是人工参考，包含类别编号和归一化框，用于训练或评价。目录中有空标签和多类别样本，后续需核验，不应把空标签自动当成正常工件。类别编号不能直接照搬网上其他版本。

**图像处理已经完成了吗？**

只完成两张内置样例的简化教学处理：3×3均值滤波减弱局部噪声；对比度拉伸扩大灰度范围；Sobel 提取梯度；按阈值和连通像素数筛选候选。结果可能包括纹理和误检，尚未在完整数据上评价，没有六类识别或质量合格认证。通用上传算法将接到 Python 后端。

**为什么不能从图片直接得到实际 XYZ？**

图片中的二维像素坐标缺乏真实尺度和深度。需相机内外参、坐标系与平面约束或深度信息。任务 5 仅利用 BlenderProc 已知相机和物体尺寸进行 XYZ 估算；普通照片默认显示不可用，不能将像素值更名为毫米。

**订单预测怎样判断好坏？**

按时间划分训练、验证和测试，未来测试数据不能参与训练；比较多个方法，报告 MAE、RMSE 等指标与测试日期。当前两个规则只展示交互，还没完成正式回测。

**为什么销售数据能用于制造课程？**

可以作为需求时序的学习材料，展示预测如何支持计划。但销量不等于订单笔数或销售额，真实排产还需要库存、工艺、产能、交付期等数据。

**能源值是不是实际测量的？**

不是。功率和时长人为设定，E=P×t，kW 乘小时得到 kWh。没有负载变化、充电损耗、电价，也没有把销量直接换算成能耗。

## 后续每个模块应补的证据

- AGV：明确目标函数和约束，比较基线与算法的总距离、总完成时间及冲突情况。
- 视觉：核验标签，分离样本集合，保留失败案例；评价候选区域与标注的匹配，而非只展示成功图片。
- 定位：验证像素定位误差；实际坐标需要标定过程和单位说明。
- 监测：明确传感器来源、标签或规则来源、时间和单位。
- 预测：时间划分、基线比较、误差指标与预测时长。
- 能源：说明参数来源、计算假设与独立手工验算。

不要把前端演示描述为全部课程算法已经完成。每名组员应能解释自己模块的输入、处理、输出与当前限制。
