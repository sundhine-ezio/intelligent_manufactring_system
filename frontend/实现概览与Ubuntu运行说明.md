## 1. 项目定位与总体结论

当前 `frontend` 是一个可以直接在浏览器里运行的 PC 端演示系统，包含：

- 统一的应用外壳：左侧导航、顶部栏、页面标题、全局错误提示；
- 五个模块：AGV 调度、视觉检测、设备状态监测（占位）、订单预测、能源节约；
- 本地示例数据：两张钢材表面缺陷图片、销售数据子集、手绘物体定位场景；
- 前端模拟逻辑：AGV 固定通道路线、电量/磨损与充电维护、图像滤波/边缘/连通区域、销量聚合与两种简单预测规则、能耗 `E = P × t` 计算；
- Mock / HTTP 两种数据模式的服务层开关；
- Node 静态文件服务器、核心逻辑单元测试和 Playwright 浏览器测试。

**它不是**：Django 后端、MySQL 数据库、真实算法模型、真实设备接入、生产级调度/避碰/预测系统。README 和 `docs/` 中也明确写了这些边界。

## 2. 技术栈（简要）

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 页面框架 | Vue 3.5.13 | 使用 CDN 风格的全局生产构建 `vue.global.prod.js`，Options API，模板写在 JS 字符串里 |
| 路由 | Vue Router 4.5.0 | Hash 模式，地址形如 `http://127.0.0.1:5173/#/agv` |
| UI 样式 | Bootstrap 5.3.3 + 自定义 `styles.css` | 只用了 Bootstrap 的 CSS，没有引入 Bootstrap JS；图标为手写 SVG |
| 图表 | ECharts 5.6.0 | 封装为 `app-chart` 组件，`ResizeObserver` 跟随容器尺寸重绘 |
| HTTP | Axios 1.13.2 | 只在 `config.mode = "http"` 时使用；Mock 模式用 `fetch` 读本地 JSON |
| 本地服务 | Node.js `node:http` | `server.mjs` 自己实现的静态文件服务器，没有 Express |
| 数据 | 本地 JSON / JPG / SVG | 无外部 CDN、无远程请求，运行时可完全离线 |
| 测试 | `node:test`、Playwright 1.56.1 | 单元测试覆盖核心纯函数；Playwright 跑桌面浏览器交互 |
| 格式化 | Prettier 3.5.3 | 仅格式化，无 ESLint |
| 构建工具 | 无 | 浏览器直接加载 `src/*.js` 原生 ES Module，没有 Vite/Webpack/TypeScript |
| 状态管理 | 无 | 每个页面用自己的 `data()` 管理状态，没有 Pinia/Vuex，刷新即重置 |

技术栈与需求文档第 11 章“逻辑分层”基本对应：页面层、通用组件、服务层、数据层是分开的；但目录没有完全照搬 11.10 的建议结构，也没有后端/数据库。

## 3. 代码结构与数据流

```text
frontend/
├─ index.html                 # 入口：加载本地 Vue/Vue Router/Axios/ECharts/Bootstrap
├─ server.mjs                 # 静态服务器，带白名单和路径穿越防护
├─ styles.css                 # 全部自定义样式
├─ src/
│  ├─ app.js                  # 应用外壳、路由、全局组件注册
│  ├─ components.js           # 图标、图表、页头、模块说明、通知、模块元数据
│  ├─ config.js               # mock/http 模式与 API 根地址
│  ├─ services.js             # Mock 服务与真实 HTTP 适配层
│  ├─ core.js                 # 地图校验、固定路线、能耗、销量聚合等纯函数
│  ├─ map-config.js           # 工厂网格地图、工位、停靠点、障碍物
│  ├─ example-vision.js       # 两张内置样例的 Canvas 图像处理
│  └─ pages/
│     ├─ home.js              # 首页
│     ├─ agv.js               # AGV 调度
│     ├─ vision.js            # 视觉检测（任务 04/05 两个标签页）
│     ├─ orders.js            # 订单预测
│     ├─ energy.js            # 能源节约
│     └─ info.js              # 设备监测占位页、使用说明
├─ assets/                    # 销售 JSON、缺陷图片、物体场景 SVG、favicon
├─ docs/                      # API 约定、演示脚本、验证记录、AI 使用说明
└─ tests/                     # 核心单元测试、Playwright UI 测试
```

### 3.1 实际路由

| 地址 | 页面 | 说明 |
| --- | --- | --- |
| `/#/` | 首页 | 五个模块入口 |
| `/#/agv` | AGV 调度 | 地图、车辆、任务、路径、统计 |
| `/#/vision` | 视觉检测 | 页内标签切换任务 04 / 05 |
| `/#/orders` | 订单预测 | 筛选、历史曲线、示例预测 |
| `/#/energy` | 能源节约 | 参数表、能耗汇总、饼图 |
| `/#/monitor` | 设备状态监测 | 占位页 |
| `/#/guide` | 使用说明 | 演示顺序与答辩提示 |
| 其他 | 重定向到 `/#/` | 没有独立 404 页面 |

### 3.2 数据流

```text
页面 data() / computed / methods
  → service（src/services.js）
    → mock：fetch assets/*.json 或调用 src/core.js 纯函数
    → http：axios → http://127.0.0.1:8000/api/
  → 页面状态更新
  → 模板渲染
```

`src/config.js` 当前是：

```js
export const config = {
  mode: "mock",
  apiBase: "http://127.0.0.1:8000/api/",
  timeout: 15000,
};
```

改成 `mode: "http"` 会走 Axios；失败时直接显示错误，**不会自动退回 Mock**。后端并不包含在本目录中。

### 3.3 几个关键实现点

- **AGV**：`map-config.js` 用 24×14 网格描述工位；`core.js` 的 `demoRoute()` 让车辆先进入中央通道 `corridorY`，再横移、再进入目标停靠点。`agv.js` 每 450ms 推进一格，顺序派单，电量低于 20% 去充电、磨损达到 80% 去维护。
- **视觉**：`example-vision.js` 对两张内置样例做灰度化、3×3 均值滤波、对比度拉伸、Sobel 边缘、连通区域筛选；上传图片只做格式/大小/解码校验和预览，点击“尝试检测”会明确提示算法未接入。
- **订单**：`assets/sales-sample.json` 是商店 1–2、商品 1–3 的 6 条完整日序列（每条 1826 天）；`aggregateSales()` 做日/周/月聚合；预测只是“重复最近 7 天”或“最近 28 天均值”，没有训练和回测。
- **能源**：`energyResult()` 逐台计算 `kWh = kW × h` 并汇总，校验空值、负值、非数字和超过 24 小时；零能耗时明确不显示占比。

## 4. 在 Ubuntu 中运行

### 4.1 前置条件

- Node.js 18 及以上（本项目在 Node v20.20.2 下验证通过；README 建议 22+）；
- npm；
- 现代浏览器（Chrome/Edge/Firefox）。

检查版本：

```bash
cd /home/sunhine/制造系统感知与决策/frontend
node -v
npm -v
```

### 4.2 安装依赖

当前目录已经有 `node_modules`，可以直接启动。如果换机器、目录被清理，或从 Windows 拷贝过来后出现权限/平台问题，建议重新安装：

```bash
cd /home/sunhine/制造系统感知与决策/frontend
npm ci
```

`npm ci` 按 `package-lock.json` 安装，版本可复现。第一次安装需要网络；安装完成后运行不需要外网。

### 4.3 启动

```bash
npm start
```

终端会输出：

```text
智能工厂演示软件：http://127.0.0.1:5173
```

在浏览器打开：

```text
http://127.0.0.1:5173
```

各模块使用 Hash 路由，例如：

```text
http://127.0.0.1:5173/#/agv
http://127.0.0.1:5173/#/vision
http://127.0.0.1:5173/#/orders
http://127.0.0.1:5173/#/energy
```

停止服务：在启动终端按 `Ctrl+C`。

> 不要直接双击 `index.html`。页面要 `fetch` 本地 JSON、加载 ES Module，必须通过 HTTP 服务打开；`file://` 方式会失败。

### 4.4 换端口

```bash
PORT=5174 npm start
```

然后访问 `http://127.0.0.1:5174`。

### 4.5 运行测试

核心逻辑单元测试：

```bash
npm test
```

本次审阅在 Ubuntu + Node v20.20.2 下实际执行，结果为 **9 项全部通过**。

浏览器交互测试：

```bash
npm run test:ui
```

但在当前 Ubuntu 环境中不能直接跑，原因有三个：

1. `playwright.config.js` 把浏览器路径写死为 Windows 的 Chrome：
   `C:/Program Files/Google/Chrome/Application/chrome.exe`；
2. 当前 `node_modules` 是从 Windows 拷贝的，`node_modules/.bin/playwright` 没有可执行权限，
   直接运行会报 `Permission denied`；
3. 本机没有安装 Playwright 对应的 Chromium。

推荐处理方式（任选其一）：

```bash
# 方式 A：重新安装依赖，修复 .bin 权限，再安装 Chromium
npm ci
npx playwright install --with-deps chromium
CHROME_PATH="$(find ~/.cache/ms-playwright -type f -name chrome | head -n 1)" npm run test:ui
```

或者修改 `playwright.config.js`，删掉 `launchOptions.executablePath`，让 Playwright 使用自己安装的浏览器：

```js
use: {
  baseURL: "http://127.0.0.1:5173",
  viewport: { width: 1366, height: 768 },
  headless: true,
},
```

然后：

```bash
npx playwright install --with-deps chromium
npm run test:ui
```

`--with-deps` 可能需要 `sudo` 安装系统库。若本机已安装 Google Chrome，也可以直接：

```bash
CHROME_PATH=/usr/bin/google-chrome npm run test:ui
```

> UI 测试只覆盖 1366×768 和 1920×1080 两种桌面分辨率，没有移动端测试。

### 4.6 Ubuntu 下的注意事项

- `启动前端.cmd` 是 Windows 批处理，Ubuntu 不使用；请用 `npm start`。
- `README.md` 中的 `npm.cmd`、PowerShell、`D:\...` 路径都是 Windows 写法，Ubuntu 上对应 `npm`、Bash、当前目录。
- `server.mjs` 固定监听 `127.0.0.1`，所以手机或其他电脑**不能**通过局域网访问。若确实需要，把 `server.listen(..., "127.0.0.1"` 改成 `"0.0.0.0"`，并放行防火墙端口；但当前页面本身没有移动端适配，见第 5 节。
- 运行时不依赖 Django/MySQL，也不需要联网；`config.mode` 默认是 `mock`。
- `server.mjs` 只允许访问 `index.html`、`styles.css`、`src/`、`assets/` 和几个 `node_modules` 下的 dist 目录；新增静态文件要同步修改白名单。

## 5. 与需求文档的主要差异

> 说明：需求文档把很多能力标为 P0/P1；当前实现是“第一版演示”，README 本身也列出了“尚未完成”。以下按模块列出**实现与需求的差异**，并不表示这些差异都是缺陷，有些是明确的阶段性取舍。

### 5.1 全局与首页

| 需求 | 当前实现 | 差异 |
| --- | --- | --- |

| 演示数据标识（FR-G-04，P0） | 顶部显示“本地演示模式”，各页有“模拟运行/教学示例/演示预测”等标签 | 基本对齐，但没有统一的全局“演示数据”徽标组件 |

| 页面不直接读原始大文件（FR-G-22） | 只读 `assets/sales-sample.json` 子集，不读 91 万行 CSV | 对齐，但数据覆盖范围远小于需求 |
